# Architecture

- **Flow:** `api.convert` → `detect` → `prepare` (stage under a clean name; LibreOffice / Chromium to PDF; scans turned upright with `/Rotate` on a copy; a URL that serves a file is downloaded) → `stream.read`: for each page, `docling_step.convert_page` (one Docling call per page) → `headings.apply` → `export_page` (+ `links.place`) → `CopyEditor.edit` per batch → page file written → images dropped → `malloc_trim`. Then the stitched `name.md`, `sidecar.save_pages` (concatenate + page-number remap), `brief.make`, report. Everything is written into a hidden staging folder that `publish.Stage` swaps in only when complete (decision 0013). HTML files are printed from their original path so relative images and styles load.
- **OCR choice:** Apple Vision on macOS; elsewhere RapidOCR, explicitly via `RapidOcrOptions` at `scan_dpi` (300) on medium/high/max (`OcrAutoOptions` drops the scale). Never raise RapidOCR's `Global.max_side_len`: its detector stretches each region's short side to 736 px, and with the 2,000 px cap lifted a thin strip became a huge image and segfaulted inside OpenCV. On our scanned sample Tesseract dropped both tables ("OSD failed"), so Tesseract is not in the image.
- **Formula/code model on CPU:** Docling runs CodeFormulaV2 in bfloat16, which took 3–5 minutes per formula on CPU in Docker. `docling_step._cpu_code_formula_options` switches it to float32 when no GPU is used (same output, about 10 s). Keep this when upgrading Docling, or `high` becomes unusable in Docker.
- **Copy-editor harness:** one `create_deep_agent` per batch with a single `submit_page` tool. A harness profile registered under `openai:gpt-6-luna` (the key Deep Agents derives from the model) hides the built-in filesystem tools and the general-purpose subagent. The tests' `ScriptedModel` reports `openai:gpt-6-luna` so the same profile applies offline.
- **No output policing (decision 0001):** nothing grades or retries model text. The only post-processing is provenance: if a submitted page differs from Docling's but the change list is empty, the assembler adds a generic `ai-edited` label. Context handed to the next page (column names of the previous page's tables, running headers, links) comes from Docling's data, never from parsing what the model wrote.
- **Memory:** Docling keeps every page image of a conversion until the result is dropped, and glibc keeps freed memory in per-thread arenas; one conversion per page plus `malloc_trim(0)` keeps RSS flat. Don't run a second Docling process (tests, another conversion) in the 7.75 GB Docker VM during a long conversion: that is what killed the first 78-page re-run.
- **Docker gotchas:** Docling models download on first use into the `model-cache` volume (`HF_HOME=/opt/cache/huggingface`). On this Mac, `docker pull` through Docker Desktop's credential helper hung; an anonymous pull with a temporary empty `DOCKER_CONFIG` worked. Never run `docker compose config`: it prints the `.env` values.
- **Git identity:** GitHub blocks pushes that expose Arjun's email, so this repo's `user.email` is his GitHub no-reply address. Commits made with another email will be rejected on push.
- **Dependencies:** `requirements.txt` pins direct deps; `requirements.lock` is `pip freeze` from the image and is used as constraints in the Dockerfile.
- **Evaluation:** private branch `eval/real-documents` keeps the blind references, scoring, visual adjudication and budget ledger in PR #4, off `main`. The entire `eval/` tree is ignored and excluded from release image builds; no merge is part of the publication plan.
- **Packaging:** `python -m everymd` and the console command are a thin wrapper around `convert()`. Runtime pins and the optional development extra mirror `requirements.txt`; Docker remains the supported runtime. The release repository starts from reviewed main files with fresh history (0017); Codex handles staging and waits for explicit public-visibility authorization (0020).
- **Repository split:** `everymd-private` retains the original history and evaluation PR #4. A separate private `everymd` holds the frozen source snapshot as one main commit. Post-snapshot launch records stay private unless the owner asks to sync them; public visibility is a separate gate.
