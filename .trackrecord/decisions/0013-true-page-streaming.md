# 0013 Truly one page at a time: Docling converts a page, the copy-editor edits it, then the next

Decided 2026-10-04. Decision 0006 meant everymd to read like a person, one page at a time, but Docling still converted the whole document before the copy-editor started and kept every page image in memory until the end (`queue_max_size=1` only limited pages waiting between stages). The evaluation's 78-page scan ran out of memory at 5.45 GB. Now each page is its own Docling conversion (`page_range=(p, p)`); the copy-editor edits it (`batch_size` pages at a time, 1 by default), its page file is written, its images are released and freed memory is handed back to the system (`malloc_trim`), then the next page is read. Measured before building: 20 pages of colbertv2 took 72 s per page-by-page against 94 s whole; RSS stayed flat at about 2.5-2.9 GB on 15 dense census pages. Built and measured on 2026-10-04: the full 78-page census scan completed (Docling only) at 3.3-3.5 GB, 4.3 GB at its densest page, 3.2 GB at the end, with all 17 sideways pages turned upright.

It also fixes the duplicated text at page breaks at its source: a whole-document conversion joined a paragraph cut by a page break into one item and exported it on the first page (24 such joins in the eval's four PDFs, at the boundaries where text was duplicated). With one page per conversion each page's text holds exactly that page.

Consequences: the Docling sidecar is joined from per-page documents (page numbers restored); heading levels come from a document-wide resolver (PDF outline, then dotted numbering) because Docling ranks levels per conversion; everything is written to a staging folder that replaces the old output only when the conversion finishes.
